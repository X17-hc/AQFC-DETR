- Origin Skill：academic-research-suite / experiment-agent；诊断纪律：diagnosing-bugs。
- Mode：已批准方案实施、合成回归与参考兼容验证。

## 1. 修复了什么，尚不能宣称什么

旧F1直接将成熟P2的重型更新从六层缩为两层。已有32图诊断显示AP从42.42降至2.74，计数、查询预算和proposal覆盖同步异常；两图P2替换干预支持特征失配这一解释。新版本不是删除报错或放宽指标，而是给每个被移除的P2更新增加一个可学习替代器，并先进行独立语义适配。

新版本固定：前两层原五尺度Encoder；第3—6层各自使用一个独立P2轻量替代器，同时执行原P3—P6更新。两个分支读取同一份更新前memory。取消本版本的6→4→2硬切换，停用末端DetailContextFusion，保留零残差局部框细化器。旧F0、旧F1配置和路径未删除或改为新算法。

**真正恢复质量仍须经适配后验收。** 未适配学生不能视为修复成功，也不能用参考六层的结果代表学生。

## 2. 核心实现契约

| 项目 | 实现 |
|---|---|
| 四个替代器 | P2/P3各1×1降至128，P3双线性对齐，DW3×3、通道LN、SiLU、1×1升至256，残差相加；末层零初始化 |
| 有效区域 | 输入padding置零，投影及输出残差再次mask；尺度顺序和proposal索引不变 |
| 参考 | 六层原Encoder，eval、no_grad；不调用教师Decoder |
| 第0适配epoch | 各替代器读取对应参考层输入，监督对应层输出 |
| 第1适配epoch | 从参考第2层输出开始真实串联学生链路；冻结低分辨率层仍允许输入梯度传播 |
| 损失 | FP32；teacher channel-RMS归一化SmoothL1＋0.25余弦项，GT Gaussian权重1＋4y，四层均值 |
| 冻结 | 只训练p2_substitutes；其他参数、buffer每轮SHA-256校验，局部框细化器冻结 |
| 学生推理 | 只走学生路径，不产生、读取或回退参考特征；GT不参与推理 |

损失仅使用trainval GT做空间加权；test GT仅用于前向后的诊断。

共同S2初始化：

```text
/workspace/AQFC-DETR/outputs/scale_v1/s2/20260924_115851_063163_8e60e76c05c3/checkpoint0002.pth
SHA-256: 40dc24835aa6f9b6b211f1d8034da4e370518bf28c2ac11cbb47e4cd8e941928
```

仅允许对应公共参数严格加载，新增局部细化器和替代器单列；适配入口另外独立检查此SHA，不因修改配置中的预训练路径而放宽来源。manifest记录新增键、参数覆盖、可训练参数清单和实际增强概率。

## 3. PyCharm中的五个新入口

解释器均为服务器现有AQFC-DETR环境，工作目录`/workspace/AQFC-DETR`。GPU只由XML环境变量`CUDA_VISIBLE_DEVICES=2`指定；不代表GPU2一定空闲，你可以启动前修改。全部使用唯一时间戳输出目录、UTF-8与无缓冲日志。

| 顺序 | 显示名称 | 作用 |
|---|---|---|
| 1 | AQFC-DETR P2迁移V2合成与参考兼容检查 | 合成回归＋FP32/AMP固定32图F0/reference兼容，不训练真实数据 |
| 2 | AQFC-DETR P2迁移V2适配20步 | **总共20次batch尝试更新**：教师输入10步＋学生串联10步；检查两阶段，不生成正式适配初始化文件 |
| 3 | AQFC-DETR P2迁移V2独立适配2轮 | 从S2重新初始化，两个完整适配epoch，不继承20步结果 |
| 4 | AQFC-DETR P2迁移V2同图质量验收 | 先32图；通过才做1000图参考—学生对照；失败停止 |
| 5 | AQFC-DETR P2迁移V2独立学生性能检查 | 通过1000图后，F0/学生/学生/F0无profile短测，不保存检测权重 |

建议下一步：手动运行第2项，确认两阶段都有有效更新、原参数/buffer不变，再运行第3项。不得从旧F1最终阶段冒烟入口开始新适配。

### 两处尚需在运行前填写的路径

没有适配结果时不能虚构输出路径，因此第4、5项明确使用`REPLACE_WITH_...`占位符，未填写会报错，不会自动挑选最近文件：

1. 两轮适配后，将第4、5项的`--adapter`改为本次生成的`adapter_initialization.pth`绝对路径。
2. 1000图验收通过后，将第5项的`--acceptance`改为该次生成的`acceptance.json`绝对路径。

第4项顺序是参考32→学生32→（通过后）参考1000→学生1000。每一对子集、权重来源、尺度、AMP与数据协议一致。它不训练、不做完整test、不搜索新方案。

## 4. 适配配方、计时和恢复

- trainval、batch2、workers2、seed42、AMP；模型公共部分eval冻结。
- 实际变换是S2的native_multiscale：640/704/768/800、max1333，无预缩小随机裁剪。继承的旧`data_aug_scales`字段不决定此模式的实际尺度。
- 原增强固定phase23，Mosaic和Copy-Paste实际概率写入manifest。
- AdamW只包含四个替代器，lr1e-4、wd1e-4、clip0.1；成功更新前500次从10%预热到100%。AMP跳步不推进预热。
- 原模型特征提取一次；参考前向、学生前向、学生反向/optimizer和整轮耗时分开保存。该工具每步末端同步用于适配计时，不能把这些时间当作正式检测吞吐。
- 20步输出每阶段`full_epoch_steps`和分段时间。按各阶段每步耗时分别估算两轮；10步短测噪声较大，需保留余量，不能套用旧检测epoch时长。

每轮保存`checkpoint0000.pth`、`checkpoint0001.pth`，第二轮完整成功后另存`adapter_initialization.pth`。后者只是模块初始化，不是假造的检测checkpoint。

中断后可以在**独立适配2轮**配置中添加：

```text
--resume /workspace/AQFC-DETR/outputs/p2_transfer_v2/adapt/<本次目录>/checkpoint0000.pth
```

保留原`--pretrained`和相同配置/AMP/workers。输出会进入新的唯一目录；只从完成的第0轮恢复第1轮。局部20步checkpoint不允许resume；不支持精确batch游标恢复。已完成两轮的checkpoint不能继续延长适配。

恢复保存模块、optimizer、scaler、RNG、成功更新、阶段、完整epoch和冻结来源签名。跨旧F1/学生/参考模式恢复会拒绝。两轮累计分段成本保存在初始化文件的`completed_metrics`中，后续F1预算必须包含适配成本。

## 5. 质量与速度验收

固定800/max1333、batch1、AMP、原动态查询与spatial，不通过固定大K掩盖退化。必须同时满足：

- AP、APvt分别下降不超过1.0个百分点。
- proposal覆盖@0.5下降不超过2.0个百分点。
- count MAE不超过参考＋max(1，参考×10%)。
- 平均查询数不超过参考120%。
- 图像覆盖、query mask、输出有限性及输入文件完整性通过。

验收文件绑定适配权重SHA、S2 SHA、图像清单和标注哈希。只有1000图通过且输入复核未变，才生成`acceptance.json`。低支持或无效AP不转换为通过。

性能检查采用50预热＋200测量、四次ABBA、同500张实际800输入、batch2/workers2/AMP。每次重置RNG、重建模型与optimizer，无参考分支，不保存短测权重；记录GPU UUID、资源采样与完整日志。5%只是继续投入的初步效率门槛，GPU竞争时不作为严格提速结论。

正式学生配置为`configs/p2_transfer/student_24e.py`。常规训练入口必须同时提供`--p2-adapter`和绑定的`--p2-acceptance`；eval验收允许未通过质量门槛的完整两轮权重，以便测量失败结果。**本次不新增自动启动24轮的配置，不执行它。**
