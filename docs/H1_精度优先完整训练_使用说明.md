# H1历史初始化联合增强：实现与手动训练说明

Material Passport：academic-research-suite / experiment-agent；implement；2026-09-26。
本文件说明工程实现，不是涨点结论。AP≥34.0、APvery tiny≥18.5仍是待验证目标。

## 1. 本次与F2不同在哪里

H1使用小论文历史检测权重 `weights/legacy/dqdetr_best305.pth`，重新开始24轮训练，
不从S2或F2终点继续。初始化文件SHA-256固定为：

`f854eec1f0d0ebf6e131d01e0b2826ce5690b593a5ed7f3fb8203453a62936e4`

保留ResNet50、五尺度、六层全尺度Encoder、六层Decoder、light_dw AQBA、DGFC和spatial候选。
没有6→4→2切换、P2学生、参考教师或适配权重。

新增三个机制（组合实验，尚不能归因于单模块）：

| 机制 | 实现 | 监督/初始化保护 |
|---|---|---|
| 语义引导细节桥接 | Encoder之后P2/P3各自融合原投影细节、masked局部对比、Encoder语义；64通道轻量处理 | 输出投影零初始化，0.1残差；padding清零；共享64通道特征供局部细化 |
| 训练期候选辅助头 | 在同一批选中候选的未detach memory上建立独立分类/回归头；最多3轮去重行Hungarian | 不增加query；从加载后的encoder检测头复制参数；权重500次成功更新内升至0.25；推理完全不调用 |
| 局部分布框细化 | 每query P2/P3各5×5采样，64通道，chunk256；中心/宽高各33个非均匀bin | 网格与DFL目标停止梯度，粗框主路径保留梯度；对称bias＋零输出权重使初始残差严格为0 |

中心支持范围为±0.5×max(粗框宽高,4输入像素)，宽高使用±log(2)的对数残差。
DFL超出支持的维度不作截断端点监督，而是排除该维；普通L1/GIoU/NWD回归仍然保留。
主匹配只用粗框一次；最终回归的细化占比由0升到0.5，DFL权重由0升到0.25，均按500次成功更新预热。
最终quality_blend针对实际输出细化框，其他辅助层和DN维持原逻辑。

辅助匹配复用当前代码实际使用的分类/L1/GIoU代价，并非另行添加NWD匹配代价。
辅助回归仍复用原L1/GIoU/NWD损失。新增监督是受控适配，不声称原创或必然涨点。

## 2. 共同初始化与历史结果的角色

历史模型有少量参数无法直接复用：旧AQBA密度编码器、现有计数/边界/密度头等。
`util/legacy_joint.py`使用已核对的精确missing/unexpected白名单；任何额外缺失或shape冲突立即失败。
每个新运行保存迁移报告和 `common_initialization.pth`（仅公共初始模型参数，不伪造optimizer/epoch）。
新增模块随机初始化不会推进公共初始化或数据增强随机流。

`outputs/p2_legacy24` 的AP31.1323 / APvt15.2318仅作为历史工程参考。
H1改变了训练尺度、额外监督和随机流组织，不能直接把差值解释成纯结构贡献。
本批不新增H0完整24轮；`control.py`仅用于共同初始化和短性能对照。

## 3. 固定训练配方

- AI-TODv2 trainval→test，普通模型，无EMA；继续9通道兼容结构，只导出有效8类。
- 新本地epoch0—23，教师、AQBA和增强课程从0开始，而非S2的phase23。
- 训练640/704/768/800，max1333，无旧预缩小/随机裁剪分支；保留原Mosaic/Copy-Paste及调度。
- batch2、workers2、seed42、AMP，AdamW、weight_decay=1e-4、clip=0.1、DN100。
- 已加载非骨干峰值LR1e-4、骨干1e-5、原投影偏移组按lr_linear_proj_mult=0.1；新增模块1e-4。
- 前500次成功更新从峰值10%线性预热；本地epoch13和23各乘0.1；AMP跳步不推进。
- 原quality_blend=0.25的一轮预热保留；新增模块预热与其独立记录。
- 每轮保存完整checkpoint。完整入口epoch23全量test；epoch0/3/7/12评估固定1000图诊断子集。
- epoch0入口在第0轮完整评估，替代同轮子集；完成评估和保存后停止，仍保留24轮LR时钟。
- test及过采样子集只作工程诊断，不据此选择研究最佳checkpoint。

## 4. PyCharm五个手动入口

| 名称 | 用途 |
|---|---|
| AQFC-DETR历史初始化与联合结构检查 | 单元、合成前反向、历史初始化兼容检查；不读训练图片 |
| AQFC-DETR H1联合增强20步及评估 | 一次20步局部训练＋2个评估batch，不自动重复24轮 |
| AQFC-DETR原主体-H1同卡短性能对照 | 固定900、800×800、batch2、workers2、50预热200测量，ABBA，无profile |
| AQFC-DETR H1历史初始化联合增强24轮 | 全24轮新训练，阶段子集诊断，最后全量评估 |
| AQFC-DETR H1历史初始化联合增强epoch0及其评估 | 完整训练epoch0＋14,018张test评估，然后停止 |

解释器 `/opt/conda/envs/AQFC-DETR/bin/python`；工作目录 `/workspace/AQFC-DETR`。
GPU仅在环境变量 `CUDA_VISIBLE_DEVICES=2` 设置，启动前可调整，不能据配置认为GPU空闲。
不使用Python Console的runfile；入口为脚本运行、UTF-8、无缓冲。

建议顺序：结构检查→20步→同卡短测→epoch0完整评估→人工决定是否续训。
不要同时启动epoch0入口和完整24轮入口，也不要把冒烟checkpoint用于正式训练。
每次warm-start创建唯一目录，不覆盖历史结果、不修改历史权重。

## 5. 停止与恢复

首轮入口使用同一个24轮配置的评估变体和 `--stop-after-epochs 1`，不是epochs=1。
完成后在实际输出目录生成 `epoch0_review.json`、`resume_command.txt/json` 和
`H1_resume_epoch1_23.run.xml`（仅完整训练、全量评估和更新统计通过时生成）。
手动复核后导入该XML，用 `--resume checkpoint0000.pth` 在同目录恢复，不能改成`--pretrained`。
恢复包括普通模型、optimizer、LR容器、scaler、成功更新数、Python/NumPy/Torch/CUDA RNG及loader RNG。
训练样本随机流按seed/epoch/index隔离；workers0/2处理同一索引获得相同增强随机流。

评估前先保存 `checkpointNNNN_pending_eval.pth`。评估失败会保留训练边界，但专用入口拒绝
把“评估未完成”当作首轮验收通过。需要先处理评估，不应删除状态或伪造complete。
不支持无损epoch中间恢复；部分冒烟checkpoint不能用于正式resume。
旧F2、P2迁移、H1及短测control之间禁止跨结构resume。

## 6. 输出与下一步判据

- `launches/<唯一ID>/console.log`：完整stdout/stderr，不受PyCharm显示缓存截断影响。
- `launch.json`：命令、源码/配置/子集hash、GPU环境、退出状态。
- `experiment_manifest.json`、迁移报告、公共初始化、每轮checkpoint、metrics.jsonl。
- 训练每1000batch、评估每2000batch显示；训练和评估分别计时。
- 新指标：P2/P3残差比例、辅助正样本数、细化混合比例、分布熵、各坐标支持区间外比例。
- `distribution_training_vt_*`使用增强后的输入像素面积，仅为训练诊断，不冒充官方VT面积协议。
- 子集目录单独保存指标与评估数组；含诊断的epoch总耗时不等于纯训练耗时。

短测只比较相同初始化、固定预算下的计算成本。步耗时增加20%对应吞吐下降16.67%，两者分别报告。
资源竞争和遥测缺失均会记录；不停止别人任务、不自动降尺度、不把GPU空闲收益算成模型收益。
实际24轮、AP/APvt增益、开销是否≤20%都必须等待手动实验，不能由合成通过推断。

若出现非有限损失、零有效更新、mask泄漏、预期之外的权重缺失，应停止后续长训练并定位。
若首轮数值正常但AP不高，先看新模块预热、候选覆盖与粗框/细化差异，不立即承诺继续24轮必涨点。
